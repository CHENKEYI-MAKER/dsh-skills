# 公司技能库：它是怎么转起来的

## 触发条件

- 用户问「公司技能库怎么用」「这些技能是哪来的」
- 用户在自己电脑上写了个技能，发现别人用不到
- 用户问「我写的技能为什么没生效」「技能怎么还没更新」
- 在本机技能目录里看到不认识的技能，想确认能不能改

## 步骤

### 1. 先搞清技能从哪来 —— 两个目录，绝不混用

| 目录 | 谁写的 | 能不能手改 |
| --- | --- | --- |
| `~/.dsh/skills/dsh-team/` | **公司下发**，员工机器上的只读副本 | ❌ 改了会被下次同步整目录覆盖掉 |
| `~/.dsh/skills/my-skills/` | **你自己写的** | ✅ 随便改，同步逻辑永不碰它 |

**服务器才是唯一权威源。** 公司那台服务器上有一份技能库，`dsh-team/` 里就是它的副本；
每 30 分钟自动拉一次，在面板上点「同步公司技能」可以立刻拉。

想确认现在是什么状态，看 DSH 面板「团队版 → 公司技能」那一行：

- `公司技能 · N 个 · 更新于 <时间>` —— 正常
- 红字 `上次同步失败（现有 N 个技能未受影响）` —— 网络或令牌问题，**技能没丢**
- 灰字 `还没绑定` —— 邀请码还没用

### 2. 想加一个公司级的技能 —— 别直接写在下发目录里

正确做法是**在你自己机器上写完，再提交给公司**：

1. 写到 `~/.dsh/skills/my-skills/<技能名>/SKILL.md`（技能名只能小写字母、数字、连字符）
2. 打开 DSH 面板「团队版 → 我写的技能」，列表里找到它
3. 点「提交审核」。提交后管理员会在看板里看到

管理员通过之后，它会进公司技能库，**半小时内下发到所有人的机器上**。

### 3. 写 SKILL.md 的四段结构

公司技能统一四段，缺一段服务端直接拒收：

```
## 触发条件   ← 什么时候该用这个技能
## 步骤       ← 给 AI 执行的具体步骤，要有判断分支
## 坑         ← 踩过的坑：❌ 错误做法 → ✅ 正确做法
## 验收标准   ← 怎么算做完了
```

frontmatter 里 **`description` 是最关键的一行**：它每次都进模型的上下文，而且是唯一决定这个技能会不会被
用起来的东西。必须写清三件事：做什么、什么时候用、什么时候**不**用。最后一条最常被漏掉，
也是避免两个技能抢触发的唯一办法。

写细一点看另一个技能 `sop-to-skill`，那是完整的方法论。

### 4. 出问题去哪看

| 现象 | 先看哪 |
| --- | --- |
| 技能没下来 | 面板「公司技能」那一行的状态；再看是不是刚提交、还没审 |
| 提交了但管理员看不到 | 面板「我写的技能」里有没有 `⚠ 名称：原因`（目录名不合语法、缺 SKILL.md、正文太短） |
| 想改公司技能 | 别改 `dsh-team/` 里的，提一个自己的版本进 `my-skills/` 再提交 |
| 想撤回自己写的技能 | 直接删 `my-skills/<技能名>/`，不影响别人 |

## 坑

- ❌ 直接改 `~/.dsh/skills/dsh-team/` 里的文件 → ✅ 只改 `my-skills/`；下发目录改了会被静默覆盖，
  你以为改好了，其实半小时后变回去了
- ❌ 技能名用中文、下划线、大写 → ✅ 只能小写字母、数字、连字符（`weekly-report` 这样）
- ❌ `description` 写成一句「销售报表」 → ✅ 写清「做什么 + 什么时候用 + 什么时候不用」，
  否则模型永远想不起来用它
- ❌ 把客户名单、手机号、报价、口令、服务器地址写进技能正文 → ✅ 用占位值（`[客户名]`、`[限额]`）。
  提交时会被自动扫描，带敏感信息的技能**连管理员也批不了**
- ❌ 同事发来一个技能文件就直接粘进 `my-skills/` → ✅ 先看它的 `description` 和后置的判断逻辑，
  技能是给 AI 执行的指令，来路不明的技能等于让别人的话进你的模型上下文

## 验收标准

- 能说出技能的两个目录分别归谁管、哪个会被覆盖
- 自己写的新技能出现在面板「我写的技能」列表里，没有 `⚠` 前缀
- 提交后能看到「已提交，等管理员审核通过后会下发给全员」
- 公司下发的技能在自己的机器上能正常触发（问一句它 `description` 里写的场景）
