# 新客户建档与录入

> ⚠️ 这是**样板技能**，用来示范"有判断分支和硬性校验"的技能该怎么写。
> 字段名与 CRM 路径是占位值，推广前必须由业务部门替换为真实系统。

## 触发条件

- 第一次接触到一个之前没有合作记录的客户，需要把它的基本信息落进系统，供后续跟进、开票、发货引用时加载本技能
- 用户会这么说：「来了个新客户」「帮我建档」「把这个客户录进系统」「他电话是 xxx」
- **不适用**：
  - 老客户的地址、联系人变更 → 走"客户资料变更"
  - 只询价、没有成交意向的线索 → 走线索池，不进正式客户档案

## 步骤

1. **查重**
   - 输入：客户全称、统一社会信用代码
   - 做什么：先在 CRM 里用**全称和信用代码各搜一遍**。查到重复就**停下**，不要新建 —— 重复档案会导致对账混乱，且后期极难合并
   - 产出：确认是"新客户"的结论，或已有客户的编号
2. **核验名称**
   - 输入：营业执照
   - 做什么：以营业执照上的**全称为准**，不要用简称、品牌名或口头叫法
   - 产出：与执照逐字一致的客户全称
3. **录字段**
   - 输入：营业执照 + 对接人 + 客户财务
   - 做什么：按下面的必填表逐个录入。必填项缺失时**向用户追问**，不要留空，也不要填"未知""待补"
   - 产出：完整的客户档案

   | 字段 | 是否必填 | 从哪拿 |
   | --- | --- | --- |
   | 客户全称 | 必填 | 营业执照 |
   | 统一社会信用代码 | 必填 | 营业执照 |
   | 联系人姓名 / 职务 | 必填 | 对接人 |
   | 联系电话 | 必填 | 对接人 |
   | 开票信息 | 必填 | 客户财务 |
   | 客户来源 | 必填 | 询问获取渠道，用于后续分析 |
   | 收货地址 | 选填 | 客户 |

4. **挂来源并分派跟进人**
   - 做什么：把客户来源标清楚（转介绍 / 展会 / 官网 / 主动联系等）；跟进人默认分派给录入人，用户指定了别人就按指定的来
   - 产出：带来源标签和跟进人的档案
5. **回执**
   - 做什么：把**客户编号和关键字段复述给用户确认**
   - 产出：用户确认过的录入结果

**判断分支**

| 情况 | 怎么做 |
| --- | --- |
| CRM 里已有同名客户 | **停止新建**，把已有编号给用户，问是否要改资料 |
| 只有手机号、没有公司全称 | 不进正式档案，先记入线索池 |
| 客户名称含括号 / 英文 | 按营业执照原样录入，不要"规范化"改写 |
| 统一社会信用代码校验不过 | 让用户核对营业执照，**不要自己改一位数字** |

## 坑

- ❌ 用简称建档（"XX生物" vs "温州XX生物科技有限公司"） → ✅ 一律用营业执照全称（原因：开票和合同会对不上）
- ❌ 没查重就新建 → ✅ 先查重，重复即停
- ❌ 必填字段填"待补" → ✅ 当场追问，问不到就不提交
- ⚠️ **信用代码校验不过时绝不能自己补一位**：那会让系统里存一个假号码，后续开票失败而且很难查

## 验收标准

- [ ] 已用**全称 + 统一社会信用代码**查重，确认是新客户
- [ ] 客户全称与营业执照逐字一致
- [ ] 6 个必填字段全部有值，且没有"未知""待补"这类占位
- [ ] 已标注客户来源，并分派了跟进人
- [ ] 已将客户编号回执给用户并获得确认
