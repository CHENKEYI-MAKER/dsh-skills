# 把访谈内容整理成技能

> 本技能负责"从访谈记录到 SKILL.md"这一段。
> **前提**：访谈已经做完（知道这个人实际是怎么干这件事的）。
> 如果还没访谈，先做访谈 —— 凭想象写的技能一定是错的。

## 触发条件

- 用户要求把某个岗位/某段流程整理成"技能"，且已经能说清流程细节时加载本技能
- 用户会这么说：「帮我写个技能」「把这个 SOP 做成 skill」「按刚才聊的整理一下」
- **不适用**：
  - 只是**修改**已有技能的文字 → 直接编辑那个 `SKILL.md`，不要新建
  - 流程还没聊清楚 → 先访谈。**没访谈就写，等于编**

## 步骤

1. **给技能起名**
   - 输入：业务用词（用户怎么称呼这件事）
   - 做什么：用**拼音或英文短横线**命名，如 `morning-sales-report`、`kehudangan-luru`。
     名字只能小写字母、数字、连字符；**目录名必须和 name 完全一致**
   - 产出：一个确定的技能名

2. **写 frontmatter**
   - 做什么：`name` + `description` + `whenToUse` + `metadata.author/version`。
     `description` 必须写清三件事：**做什么 / 什么场景触发 / 什么时候不适用**
   - 产出：可被模型正确触发的描述

3. **写「## 触发条件」**
   - 做什么：把"什么情况加载本技能""用户会怎么说（原话关键词）""不适用什么"三段写清
   - 产出：触发边界

4. **写「## 步骤」**
   - 做什么：**按用户口述的顺序编号**，不要替用户重新设计流程。每步写清：
     **做什么 / 输入是什么（从哪拿，拿不到怎么办）/ 产出是什么**
   - 产出：可执行的步骤清单

5. **写「## 坑」**
   - 做什么：把访谈中提到的**易错点、特殊要求**逐条列出，格式
     `❌ 错误做法 → ✅ 正确做法（原因：为什么）`；特别重要的用 `⚠️` 单列
   - 产出：避坑清单

6. **写「## 验收标准」**
   - 做什么：写成可勾选的检查项 —— **"做完了"和"做得让人满意"分别是什么**
   - 产出：验收清单

7. **写入并自检**
   - 做什么：
     1. 写到技能目录：`skills/<技能名>/SKILL.md`
     2. **写完必须自己读一遍确认文件存在、内容完整**（不许凭记忆说"已写好"）
     3. 跑校验器（如果技能库里有 `tools/validate.mjs`）：
        ```sh
        node tools/validate.mjs
        ```
   - 产出：通过校验的技能文件

8. **向用户确认**
   - 做什么：用**三行**汇报 —— 技能名 / 触发场景 / 步骤数，请用户确认。
     用户说「可以」才算完成；说要改就改完**再确认一次**
   - 产出：用户确认过的技能

## 坑

- ❌ **在技能里写需要用户回答的技术问题**（如"你需要用哪个工具？""你的环境是 Mac 还是 Windows？"）
  → ✅ 环境判断、工具选择、命令参数**一律写成执行者自判**
  （原因：技能的读者是 AI，不是人。留下需要人回答的技术问题，技能就没法自动执行）
- ❌ 凭想象补全流程细节 → ✅ 只写访谈里真实说过的；没说清的回去问
- ❌ 写入后不核实，直接汇报"已完成" → ✅ **读完确认文件真的存在**再汇报
- ❌ 把访谈里的**真实客户名、金额、口令、服务器 IP** 原样写进技能
  → ✅ 换成占位值（`[客户名]`、`[限额]`）
  （原因：技能库若是公开仓库，这些是真泄露）
- ⚠️ 用户口述的顺序**不要"优化"**：他觉得第 3 步在第 2 步之前，就照他的来 —— 他才知道现场怎么走
- ⚠️ 技能名一旦定下就别改：改了等于换了一个技能，已装的人不会自动更新

## 验收标准

- [ ] 技能名 = 目录名，且符合 `^[a-z0-9]+(?:-[a-z0-9]+)*$`
- [ ] frontmatter 的 `description` 写清了"做什么 / 何时触发 / 何时不用"
- [ ] 四个标准小节齐全且顺序正确：`## 触发条件` → `## 步骤` → `## 坑` → `## 验收标准`
- [ ] 步骤按**用户口述顺序**编号，每步都有"输入 / 做什么 / 产出"
- [ ] 技能里**没有任何需要用户回答的技术问题**
- [ ] 不含真实客户名、金额、口令、IP 等敏感信息
- [ ] **已读回文件确认存在**，且校验器通过（`node tools/validate.mjs` 退出码 0）
- [ ] 已用三行（技能名 / 触发场景 / 步骤数）向用户汇报并得到"可以"
